# Remotion — видео из кода (React)

## Что это простыми словами и чем отличается от Higgsfield

Higgsfield (`docs/higgsfield.md`) генерирует видео по текстовому описанию — AI сам придумывает, что показать, результат каждый раз слегка разный и не полностью предсказуемый. Remotion — противоположность: **ты сам пишешь код, который определяет каждый кадр**, и результат абсолютно детерминирован — один и тот же код всегда даёт один и тот же ролик.

**Конкретный пример, где Remotion выигрывает, а AI-генерация — нет:** нужно сделать 500 персонализированных видео-открыток «С днём рождения, {Имя}!» — по одной на каждого клиента из CSV-файла. Просить AI-генератор сделать 500 отдельных видео дорого и непредсказуемо (в каждом видео текст может выглядеть по-разному). С Remotion — пишешь ОДИН React-компонент с именем как переменной, а дальше рендеришь его 500 раз с разными данными — быстро, дёшево (просто вычисления, не AI-генерация) и все видео идеально одинаковы по стилю.

Другие типичные задачи для Remotion: субтитры/капшены, дата-визуализации в движении (график, который растёт на видео), программные анимации логотипа, видео-отчёты по шаблону.

**Никакого API-ключа не нужно** — это чистая JS/React-библиотека, рендерит локально на твоей машине (или в облаке, см. ниже — опционально). Никак не завязана на Claude/Anthropic/другие AI-провайдеры.

**Лицензия:** бесплатно для команд до 3 человек и для личного использования; если у тебя компания больше — нужна отдельная лицензия ([подробности](https://github.com/remotion-dev/remotion/blob/main/LICENSE.md)).

## Что установлено сейчас

Готовый стартовый проект (`--blank` шаблон) лежит в папке [`remotion/`](../remotion) этого репозитория:

```bash
cd remotion
npm i          # уже сделано при установке
```

Проверено реальным рендером — `npx remotion render` собрал рабочий `out/MyComp.mp4` (88.6 kB, 60 кадров @ 30fps). `node_modules` и `out/` в `.gitignore`, в git попадает только сам проект (исходники, конфиг).

## Структура проекта

```
remotion/
├── src/
│   ├── Root.tsx          — реестр композиций (какие видео вообще есть)
│   ├── Composition.tsx   — сама композиция + React-компонент, который рендерится
│   └── index.ts          — точка входа
├── public/                — статика (картинки, шрифты, музыка)
└── remotion.config.ts     — конфиг рендера
```

Одна композиция — это `<Composition id="..." component={...} durationInFrames={...} fps={...} width={...} height={...} />` в `Root.tsx`. Можно завести сколько угодно композиций — разные видео в одном проекте.

## Как этим пользоваться

**1. Визуальный превью-редактор (Remotion Studio) — открывается в браузере:**

```bash
cd remotion
npm run dev
```

Живой предпросмотр с таймлайном — правишь `src/Composition.tsx`, видишь изменения сразу.

**2. Рендер готового видео:**

```bash
npx remotion render                    # рендерит первую композицию
npx remotion render MyComp out/final.mp4   # конкретная композиция → конкретный файл
```

**3. Рендер одного кадра (картинка вместо видео):**

```bash
npx remotion still MyComp out/frame.png
```

**4. Посмотреть, какие композиции есть в проекте:**

```bash
npx remotion compositions
```

**5. Обновить Remotion до последней версии:**

```bash
npx remotion upgrade
```

## Как писать сам ролик

Правишь `src/Composition.tsx` — это обычный React-компонент. Главное отличие от веб-React: время. Хук `useCurrentFrame()` даёт номер текущего кадра, из него считаешь анимацию:

```tsx
import { useCurrentFrame, interpolate } from "remotion";

export const MyComponent: React.FC = () => {
  const frame = useCurrentFrame();
  const opacity = interpolate(frame, [0, 30], [0, 1]); // фейд-ин за первые 30 кадров

  return <div style={{ opacity }}>Привет из Remotion</div>;
};
```

Дальше — обычный React: пропсы, стейт (для статичных значений, не для анимации кадра), любые библиотеки. Данные (CSV/JSON) можно подключать через `calculateMetadata` в `Composition.tsx`, чтобы генерировать разное число кадров/разный контент под разные данные — это основа для «пачки персонализированных видео».

### Полный пример: сделать и отрендерить готовое видео с нуля

1. `cd remotion && npm run dev` — открывается Remotion Studio в браузере, сразу видно текущую (пустую) композицию
2. Правишь `src/Composition.tsx` — добавляешь текст с анимацией (пример выше) — сохраняешь, в браузере превью обновляется мгновенно, без перезапуска
3. Доволен результатом — `npx remotion render` в терминале — получаешь `out/MyComp.mp4`, готовый файл
4. Если нужна версия под другого клиента с другим текстом — меняешь проп/данные и рендеришь снова, компонент тот же

Для «пачки видео под разных людей» — передаёшь в `<Composition>` пропы с данными (имя, число) через `defaultProps` или `calculateMetadata`, и рендеришь одну и ту же композицию много раз с разным входом, вместо того чтобы переписывать код под каждое видео.

Рендер в облаке (Google Cloud Run) — опционально, статус Alpha — описан в справочнике команд ниже.

## Справочник команд

Все команды выполняются из папки `remotion/` (`cd remotion` сначала).

#### `npm run dev` (= `remotion studio`)
- **Что делает:** открывает Remotion Studio — визуальный редактор-превью в браузере с таймлайном, плеером и live-reload при правке кода.
- **Когда использовать:** всегда первым шагом, когда пишешь/правишь композицию — видишь результат сразу, без рендера.

#### `npx remotion render`
- **Что делает:** рендерит композицию в готовый видеофайл (MP4 по умолчанию).
- **Синтаксис:** `npx remotion render [composition-id] [output-location] [флаги]`
- **Ключевые флаги:**
  - без аргументов — рендерит первую композицию в `out/<id>.mp4`
  - `npx remotion render MyComp out/final.mp4` — конкретная композиция в конкретный файл
  - `--codec h264|h265|vp8|vp9|prores|gif` — формат кодирования
  - `--crf <число>` — качество/сжатие (меньше число = выше качество, больше файл)
  - `--frames 0-99` — отрендерить только диапазон кадров, а не всё видео
  - `--concurrency <N>` — сколько кадров рендерить параллельно (быстрее на многоядерной машине)
  - `--props '{"name":"Иван"}'` — передать данные в композицию снаружи, не меняя код (для «пачки персонализированных видео»)
- **Пример:** `npx remotion render MyComp out/ivan.mp4 --props '{"name":"Иван"}'`

#### `npx remotion still`
- **Что делает:** рендерит один конкретный кадр как картинку (PNG/JPEG), а не всё видео.
- **Синтаксис:** `npx remotion still [composition-id] [output.png] [--frame <номер>]`
- **Пример:** `npx remotion still MyComp out/frame.png --frame 45`
- **Когда использовать:** нужен превью-кадр для обложки/тамбнейла, не весь ролик.

#### `npx remotion compositions`
- **Что делает:** печатает список всех композиций, объявленных в `src/Root.tsx`, с их id, длительностью, разрешением.
- **Когда использовать:** проверить, что видно Remotion, перед рендером конкретной по имени.

#### `npx remotion bundle`
- **Что делает:** собирает проект в статический бандл (используется внутри `render`/`still`, но можно вызвать отдельно для кэширования/CI).

#### `npx remotion upgrade`
- **Что делает:** обновляет `remotion` и все пакеты `@remotion/*` до последней совпадающей версии одной командой (версии должны совпадать друг с другом — руками обновлять рискованно).

#### `npx remotion add <пакет>`
- **Что делает:** добавляет официальный Remotion-пакет (например `@remotion/cloudrun`, `@remotion/lottie`, `@remotion/captions`) с правильной, совпадающей версией.
- **Пример:** `npx remotion add @remotion/cloudrun`

#### Облачный рендер (`@remotion/cloudrun`, после `npx remotion add @remotion/cloudrun`)

- **`npx remotion cloudrun services deploy`** — разворачивает Cloud Run сервис на твоём GCP-проекте
- **`npx remotion cloudrun sites create`** — выкладывает текущий проект в Google Cloud Storage
- **`npx remotion cloudrun render <serve-url> <composition-id>`** — запускает рендер в облаке вместо локальной машины

Нужен отдельный **GCP-проект с биллингом** и `gcloud auth application-default login` — статус фичи **Alpha**, для большинства задач локального `npx remotion render` достаточно.
