# Headroom — сжимает контекст, который читает Claude (меньше токенов)

## Что это простыми словами

Когда Claude Code работает, он не только читает твои сообщения — он ещё читает результаты своих же команд: вывод `grep`, содержимое файлов, логи ошибок, историю переписки. Всё это идёт в модель как «контекст» и **стоит денег и места** — у сессии есть лимит токенов, и чем больше мусора в контексте, тем быстрее он забивается и тем дороже каждый запрос.

**Конкретный пример:** просишь Claude найти баг — он делает `grep` по логам и получает 10 000 строк вывода. Из них реально важны 5 строк рядом с ошибкой. Без Headroom все 10 000 строк уходят в модель как есть. С Headroom это сжимается до содержательного ядра — по бенчмаркам авторов такой сценарий (разбор инцидента) даёт **−92% токенов**, при этом Claude находит тот же баг, потому что суть не потеряна.

Headroom — не отдельная нейросеть и не замена Claude. Это прослойка, которая перехватывает то, что идёт **в** модель (или то, что модель уже прочитала — зависит от режима), сжимает, и передаёт дальше. Ответы остаются такими же по качеству, токенов уходит в разы меньше.

**Другие цифры из бенчмарков:** поиск по коду −92%, разбор GitHub issue −73%, обход кодовой базы −47% токенов — без потери точности на стандартных тестах (GSM8K, TruthfulQA).

**Работает с обычной подпиской на Claude.** Никакого отдельного API-ключа не нужно — Headroom просто становится «прослойкой» между Claude Code и Anthropic API (или другим провайдером), которую уже используешь. Всё считается локально на твоей машине, ничего никуда не отправляется.

## Что установлено сейчас

CLI `headroom` (v0.37.0) уже стоит в этом облачном окружении (`uv tool install "headroom-ai[all]"`), для проверки — `headroom doctor` отрабатывает и корректно показывает, что прокси/обёртка пока не включены. **Реальной пользы это здесь не даёт**: Headroom работает, либо (а) запуская локальный прокси-процесс, который должен крутиться всё время сессии, либо (б) регистрируя MCP-сервер в твоём личном `~/.claude.json` — то и другое живёт на конкретной машине, а не в этой одноразовой облачной сессии. Поставить по-настоящему полезно нужно там, где у тебя постоянно работает Claude Code (свой ноутбук).

## Установка на своей машине

```bash
uv tool install --python 3.13 "headroom-ai[all]"   # рекомендуемый способ (или: pip install "headroom-ai[all]")
```

## Как этим пользоваться — три режима

Выбирай по тому, сколько усилий готов вложить и насколько важна максимальная экономия.

### Режим 1 — «поставил и забыл» (рекомендуется для начала)

Одна команда вместо обычного запуска `claude`:

```bash
headroom wrap claude
```

Что происходит: Headroom поднимает у себя в фоне локальный прокси-сервер, и запускает Claude Code так, чтобы весь его трафик к Anthropic шёл через этот прокси. Дальше просто работаешь с Claude Code как обычно — ничего не меняется в том, как ты им пользуешься, просто счёт по токенам меньше. Никаких `--proxy-url` и прочих флагов помнить не нужно.

Отменить (вернуть обычный запуск без прокси):
```bash
headroom unwrap claude
```

### Режим 2 — лёгкий, по запросу (без фонового процесса)

Если не хочешь держать фоновый прокси-процесс постоянно запущенным, но хочешь дать самому Claude возможность сжимать что-то по своей инициативе:

```bash
headroom mcp install   # один раз — регистрирует Headroom как MCP-инструмент для Claude Code
claude                 # дальше обычный запуск, без обёртки
```

Теперь у Claude есть три новых инструмента, которые он вызывает сам, когда решит, что это уместно:
- `headroom_compress` — «сожми вот этот большой кусок текста, который я только что прочитал»
- `headroom_retrieve` — «а можно оригинал целиком, вдруг я что-то упустил при сжатии»
- `headroom_stats` — «сколько я вообще сэкономил за сессию»

Разница с режимом 1: здесь сжимается не *весь* трафик автоматически, а только то, что Claude сам решит отправить на сжатие — легче в настройке, но менее полное покрытие.

### Режим 3 — полный контроль (максимальная экономия)

Ручной запуск прокси и явная настройка Claude Code на работу через него — для тех, кто хочет видеть оба процесса раздельно (например чтобы смотреть логи прокси отдельно):

```bash
headroom proxy --port 8787                              # терминал 1 — держим прокси открытым
ANTHROPIC_BASE_URL=http://127.0.0.1:8787 claude          # терминал 2 — Claude Code с трафиком через прокси
```

По сути то же самое, что делает `headroom wrap claude` из режима 1 «под капотом» — просто руками, в двух отдельных терминалах.

## Как проверить, что реально работает

```bash
headroom doctor       # health-check: подключён ли прокси, куда идёт трафик, что не так
headroom dashboard     # живой дашборд с цифрами экономии в браузере (нужен запущенный прокси)
headroom perf          # быстрая проверка производительности сжатия
```

`headroom doctor` — первое, что стоит запустить после любой настройки: он прямо скажет, что подключено, а что нет, и что нужно сделать, чтобы включить недостающее.

## Когда это реально нужно (по словам авторов)

- **Хорошо подходит:** пользуешься AI-агентами каждый день и хочешь экономить токены/деньги без правок кода; работаешь сразу в нескольких агентах (Claude, Codex, Cursor...) и хочешь, чтобы у них была общая память между собой.
- **Можно пропустить:** если работаешь в песочнице, где локальные фоновые процессы вообще не запускаются (как раз наш случай прямо сейчас, в этой облачной сессии) — или тебе и так хватает штатного сжатия контекста, которое уже даёт сам провайдер.
